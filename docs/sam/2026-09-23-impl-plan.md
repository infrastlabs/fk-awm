### 5、Spike 2 —— LGI shim 最小闭环

> 目标：证明 shim 骨架的形态是对的、行数在预期范围内。这是 R6 的核心攻关项，也是 Phase 2 施工的直接前置。

**动手前必读：实现级硬约束（b16 一·2 L73-80、三·4）**

Spike 2 只写 stub 骨架，但骨架形态必须满足以下 4 条硬约束，否则 Phase 2 施工时会在 C 边界上崩溃：

1. **shim 对象必须是 full userdata**，不是 table。`lib/objects/client.c:4335`（`shape_input`）、`luaa.c:316`（`pixbuf_to_surface`）等 C 侧用 `lua_touserdata` 取对象，table 包装方案在这些边界直接 NULL 崩溃。
2. **`._native` 恒返回 lightuserdata**（裸指针）—— 穿越 C 边界的唯一通道；oocairo 需要补 `._native` 小补丁。
3. **所有 userdata 实现 `__gc` 终结器**（`g_object_unref` / `cairo_surface_destroy` / `rsvg_handle_free`）—— LGI 靠 GC + 显式 `:finish()` 双通道释放，shim 必须自己补齐 GC 通道。
4. **跨绑定取裸指针** —— `PangoCairo.create_context` / `Rsvg.render_cairo` 都要从 cairo Context userdata 解出 `cairo_t*`，需要一个通用 unwrap 机制（oocairo 补丁或内部 userdata→ptr 表）。

骨架阶段不实现这 4 条也可以编译过，但要在注释里标注「Phase 2 必须实现」，避免后面忘。

### 1、Phase 2 前的风险清单（b16 一·6）

Spike 2 只写 stub，但 Phase 2 施工时会踩到以下风险。**动手前必须先记下来**。

| 风险 | 等级 | 说明 | 缓解 |
|------|------|------|------|
| GLib closure guard | 高 | `g_source_*` 的 closure 生命周期由 GLib 管理，shim 释放时机错了 → 随机段错误，堆栈不指向绑定代码 | GLib 绑定实现时先做「closure guard」测试：注册 → 移除 → 释放全流程 |
| cairo surface 类型判别 | 中（排查成本最高） | `lib/gears/surface.lua` 第 35/48/70/109/119 行 5 处 LGI cairo surface 类型判断（源码注释 `-- Try to convert the argument into an lgi cairo surface.`）。shim 必须提供 `__typename` 字段，否则 `_to_surface` 等转换**静默失败**（不报错，只是画不出图） | shim 的 cairo 对象 metatable 必须带 `__typename = "cairo_surface_t"` / `"cairo_t"` |
| `a_glib_poll` Lua 栈断言 | 中（隐蔽） | `awesome.c:460-464` 每次 poll 断言栈顶为 0；手写绑定 C 回调里操作栈后没清干净 → warn 刷屏 + 随机行为（不是崩溃，更难定位） | 所有 GLib C 回调函数返回前 `lua_settop(L, 0)` |
