## A 类 · 确定缺口（源码 + 二进制 strings 双向实证）

### 🔴 A-1 `cairo.Context:user_to_device_distance` — 头号风险，冒烟测不到
- **缺什么**：`lgishim_cairo.c` `CTX_M`（2013 行起，74 条）无此项。`strings -a awesome | grep -c '^user_to_device_distance$'` = **0**
- **调用点**：`lib/wibox/widget/systray.lua:75` `local dir_x, dir_y = cr:user_to_device_distance(1, 0)`
- **踩到条件**：任何 `wibox.widget.systray` 的 wibox 被重绘。**默认 `rc.lua:195` 就有 `wibox.widget.systray()`**
- **为什么冒烟是绿的**：`systray.lua:51` `should_display_on()` 在 `screen.primary` 为 nil 时整段 `draw` 短路返回；而 `objects/screen.c:1449` `screen_update_primary()` 在 `!globalconf.have_randr_13` 或 `xcb_randr_get_output_primary` 无匹配时 `primary_screen` 保持 NULL。Xvfb 无真实 primary output → 短路。**真实 RandR 1.3+ 桌面必然踩到**，崩在 wibox 重绘而非 rc.lua 加载，冒烟的 grep 判据抓不到
- **严重度**：高（标题栏/状态栏整体不渲染，但 awesome 不退出 → 静默坏）

### 🔴 A-2 `cairo.Context:new_sub_path`
- **缺什么**：`CTX_M` 无此项（strings = 0）。`lgishim_cairo.c:1844` 只在 `ctx_circle` **内部**调用了 C API `cairo_new_sub_path`，未导出 Lua 绑定
- **调用点**：`lib/gears/shape.lua:287`（`partially_rounded_rect`）、`:622`（`pie`）、`:661`（`arc`）
- **踩到条件**：`wibox.container.background:set_shape(gears.shape.partially_rounded_rect)` / `shape.arc` / `shape.pie`。`lib/naughty/container/background.lua:39` `wdg:set_shape(shape)` 默认回落到 `gshape.rectangle`（**不需要** new_sub_path，`rounded_rect` 同样不需要），但只要用户在 rc 里设 `beautiful.notification_shape = gears.shape.partially_rounded_rect` 就崩
- **概率**：高（圆角 wibox 是 awesome 社区最常见定制之一）

### 🟠 A-3 `GLib.Timer:stop / :continue / :start`
- **缺什么**：`lgishim_glib.c:729` `TIMER_M` 只有 `new` + `elapsed`
- **调用点**：`lib/wibox/container/scroll.lua:232`（`pause`）、`:244`（`continue`）、`:255,:257`（`reset_scrolling`）
- **踩到条件**：`wibox.container.scroll` 且调用 `:pause()`/`:continue()`/`:reset_scrolling()`
- **重要**：`scroll.lua:425` 构造 `GLib.Timer()` 正常，`:131` `self._private.timer:elapsed()` **每帧重绘都调**且已实现 → 滚动动画本身能跑，只有那 3 个控制方法崩
- **概率**：中（scroll 常用，但那 3 个方法较少调）

### 🟠 A-4 `cairo.Surface:write_to_png`（**本次审计新发现，文档全篇未提**）
- **缺什么**：`lgishim_cairo.c` `SURF_M`（1090 行起，15 条）无此项，即 cairo 1.15 的 `cairo_image_surface_write_to_png`

- **踩到条件**：`awful.screenshot` 的 `:save()` / `:accept()`。全库仅此 1 处（另 `objects/client.c:939` 是注释示例）
- **概率**：中——默认 rc 无 Print 键绑定，但截图是最高频用户自加键绑定之一，一按就崩

### 🟡 A-5 `cairo.SvgSurface.create`

## 排序（踩到概率 × 严重度）

1. **A-1 systray `user_to_device_distance`** — 默认 rc 自带 systray，真实桌面必踩，冒烟结构上测不到
2. **A-2 `new_sub_path`** — 三个常用形状函数，wibox 圆角是最高频定制
3. **A-3 `Timer:stop/continue/start`** — scroll 常用但触发需显式调 pause/continue
4. **A-4 `write_to_png`** — 截图保存，用户自加键后必踩，**文档完全未记录**
5. **A-5 `SvgSurface.create`** — 两个 API 都偏冷门，`widget_to_svg` 已 deprecated
6. **A-6 `pixbuf_get_from_surface`** — spec only

## 需要提醒的两点

1. **A-1 的根因不是 shim 缺陷 alone，而是冒烟判据失效**：`screen.primary` 在 Xvfb 下为 nil 使 `systray:draw` 整段短路，等于默认 rc 里 systray 从未被执行过。同样的短路模式可能还在掩盖其它「只在真实多屏/RandR 环境生效」的路径。建议补一个「强制 `screen.primary` 非 nil」的冒烟用例，或改成断言 `wibox:draw` 被调用。
2. **发布产物落后 2 个提交**：`awe-package` 里 `sha=1b03351`，而 HEAD 是 `bf6ee42c`，中间隔着 `fb67b582`（rc.lua 启动修复 + `lgishim_cairo.c` lightuserdatum 修复 + gio traceback）和 `48b55080`。当前那份「0 错误」冒烟日志对应的二进制**不含**这些修复，下一轮出包前需重跑 step 5–6。
