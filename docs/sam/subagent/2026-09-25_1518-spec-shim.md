## 加载机制（调研结论）
- `spec/preload.lua` 是 busted 的 `--helper` 文件，原来直接 `require "lgi"` → 命中系统 lua-lgi 0.9.2（`/usr/share/lua/5.3/lgi.lua`）。
- lib/ 侧走 `require("vendor.lgishim")`，而 shim 的 C 部分只在 awesome 二进制里可达——`luaa.c:1141-1159` 把 7 个 `luaopen_lgishim_*` 塞进 `package.preload`，busted 用的独立 `lua5.3` 没有这个注册表。所以历史跑法对 shim 完全失明。
- `lib/vendor/lgishim.lua:18` 用 `pcall(require, "lgishim_pango")` 探测，探测不到就静默退化到真 lgi——这正是"绿灯但没测到 shim"的来源。

## 改动（2 个文件；未碰 lib/、未碰 lib/vendor/*.c）
1. `spec/preload.lua:17-26`：`LGI_SHIM_CDIR` 预置 `package.cpath`；先 `require("vendor.lgishim")`；若 `lgi.shim == true` 则 `package.preload["lgi"]` 指向**同一个表**，两种写法拿到同一对象，保住 shim 的 `is_type_of()` 元表判断。变量不设 → 回退真 lgi，与历史行为完全一致。
2. `docs/sam/scripts/12-spec-shim-loader.sh`（新增，755）：把 6 个 `lgishim_*.c` 编成**一个** `.so`，再 hardlink 成 7 个模块名——`dlopen` 按 inode 去重，交叉调用（`lgishim_cairo.c`→`lgishim_pango_check_layout`；`lgishim_gio.c`→`lgishim_gobject_check_closure`）落在同一映射内解析，静态符号表不重复。动态链 pkg-config 的 glib/gio/cairo/pango/gdk-pixbuf，`-I/usr/include/lua5.3` 对齐 busted 的解释器。带 backend 闸门（真回退了就 `exit 2` 中止）+ fixture 权限 trap。
